# Performance Manager

Obsidian을 사용하면서 플러그인별로 확인된 처리 시간을 많이 쓴 순서로 보여주는 데스크톱 전용 플러그인입니다.

## 사용 방법

### 플러그인 관리 (0.2.7)

왼쪽 리본의 **퍼즐 + 톱니바퀴** 아이콘(플러그인 관리), 명령 팔레트의 **Performance Manager: 플러그인 관리**, 또는 설정의 Performance Manager에서 **플러그인 관리 열기**를 누릅니다.

1. **+ 그룹 만들기**로 그룹 이름을 정합니다.
2. **수정**을 누르면 선택 체크박스가 나타납니다. 클릭으로 선택하고 **Shift+클릭**으로 구간을 추가 선택합니다. 이미 선택한 항목은 유지하며, 직접 클릭한 항목이 다음 구간의 시작점입니다. 체크만으로 켜짐 상태는 바뀌지 않습니다.
3. **그룹에 추가**를 누르고 팝업에서 그룹을 검색하여 선택합니다. 플러그인은 한 그룹에만 속하며, 다른 그룹에 추가하면 소속을 이동합니다. **완료**를 누르면 체크박스를 숨깁니다.
4. 왼쪽에서 그룹을 검색하거나 이름을 눌러 그 그룹만 봅니다. 그룹 이름 아래에 **전체 N개 / 켜짐 M개**를 따로 표시하며, 켜진 개수는 현재 실제 활성 상태에 따라 갱신합니다. 그룹 토글을 끄면 소속 전체를 끄고, 다시 켜면 평소 개별적으로 정한 켜짐·꺼짐 조합을 복원합니다. 일부만 켜져 있어도 그룹은 사용 중으로 표시하며, 누르면 전체를 끕니다. Performance Manager 자신은 끄기 대상에서 제외합니다.
5. **⋮**에서 Obsidian의 기본 메뉴를 엽니다. **설정 / 단축키 / 세부 정보 보기 / 커뮤니티 페이지 열기 / 후원 / 폴더에서 보기 / 삭제**를 지원합니다. 설정·단축키·후원은 해당 플러그인이 제공할 때만 나옵니다. 삭제는 Obsidian의 확인창을 거칩니다. Obsidian 1.14.4에서 확인했으며, 기본 메뉴 생성 기능이 없는 구버전에서는 기존 설정·단축키 메뉴를 사용합니다.

그룹 **⋮ → 하위 그룹 만들기**로 2단계 하위 그룹을 추가할 수 있습니다. 기존 소속은 그대로 유지하며, 부모 이름을 선택하면 직접 소속과 하위 그룹 항목을 함께 표시합니다. 자식 이름을 선택하면 해당 항목만 표시합니다. 이름 앞 화살표로 접고 펼칩니다. 부모 개수는 하위 항목까지 합산하며, 부모 스위치는 하위 항목도 함께 끄고 각 그룹이 기억한 조합으로 복원합니다. 하위 그룹 삭제 없이 부모만 삭제하면 자식은 독립 그룹으로 유지됩니다.

왼쪽 그룹 이름을 드래그하면 그룹 순서를 바꿀 수 있습니다. 그룹 가운데에 놓으면 하위 그룹으로 이동하며 테두리를 강조합니다. 위·아래에 놓으면 놓일 위치를 보라색 선으로 표시하며, 순서는 재시작 후에도 유지됩니다. 순서 변경은 소속이나 켜짐 상태를 바꾸지 않습니다.

왼쪽 그룹 **⋮**에서 이름을 바꾸거나 그룹을 삭제할 수 있습니다. 그룹을 삭제해도 플러그인을 삭제하거나 끄지 않습니다. 특정 그룹을 선택한 뒤 플러그인을 체크하고 **그룹에서 빼기**로 소속을 해제할 수 있습니다.

수정 모드에서는 플러그인 행을 왼쪽 그룹으로 끌어 소속을 옮길 수 있습니다. 여러 개를 체크한 뒤 선택된 행을 끌면 선택 항목 전체가 함께 이동합니다. 선택하지 않은 행을 끌면 그 항목만 이동합니다. **켜진 플러그인**에 놓으면 소속을 해제하며, 이동 중 Esc로 취소할 수 있습니다. 드래그 이동은 켜짐 상태를 바꾸지 않습니다.

**켜진 플러그인**에는 일괄 토글이 없습니다. 모든 목록에서 **수정 → 여러 항목 체크 → 선택한 항목 하나의 토글 조작**으로 선택 전체를 켜거나 끕니다. 선택하지 않은 행의 토글은 그 플러그인에만 적용됩니다. 기존 그룹 소속은 유지되며, Performance Manager 자체는 끄기 대상에서 제외합니다.

실제 **설정 → 커뮤니티 플러그인**에서도 같은 그룹을 접고 펼쳐 봅니다. 원래 플러그인 행·메뉴·토글을 유지하며, 기본 검색 결과가 접힌 그룹에 있으면 검색 중 펼쳐 표시합니다. 그룹 구성과 접힘 상태는 재시작 후 유지됩니다. 설정창 왼쪽의 전체 설정 검색에서 플러그인 결과를 선택하면 해당 그룹을 펼치고 원래 설치 목록의 항목으로 바로 이동합니다.

창의 빈 부분을 잡아 이동하고, 바깥 네 변과 모서리를 잡아 크기를 조절합니다. 목록·버튼·입력칸을 조작할 때는 창이 움직이지 않습니다. 좌우 구분선으로 그룹 목록 너비를 조절하며, 창 위치·크기·좌우 너비는 재시작 후 유지됩니다.

**켜진 플러그인**에는 그룹 없는 켜진 항목만, **꺼진 플러그인**에는 그룹 없는 꺼진 항목만 표시합니다. 그룹에 속한 플러그인은 두 목록 모두에서 제외합니다. **각 그룹**에는 설치된 소속 항목 전체를 표시하며, 꺼도 행·소속·개수가 유지됩니다. 그룹을 껐다 켜도 두 목록의 숫자는 바뀌지 않습니다. ‘전체 플러그인’ 항목과 ‘꺼진 플러그인 숨기기’ 토글은 없습니다.

그룹 내부의 켜짐·꺼짐 조합은 자동으로 기억합니다. 개별 또는 다중 선택으로 바꾸거나 기본 커뮤니티 플러그인 설정에서 개별 전환하면 해당 항목의 기억만 갱신합니다. 그룹 전체 끄기는 기억을 덮어쓰지 않으며, 별도 상태 저장 버튼·토글은 없습니다. 기억한 항목이 모두 꺼짐이면 임의로 전부 켜지 않고 안내합니다. 그룹 이동 시 실제 활성 상태는 유지하며, 새 그룹은 이동 당시의 상태를 기억합니다. 처음 업데이트하거나 앱을 시작하는 것만으로 플러그인을 켜지 않습니다.

일괄 전환은 순서대로 실행하고, 실패하면 해당 작업에서 변경한 항목을 복구합니다. 복구 실패는 화면에 표시하며, 중단된 작업은 다음 시작 시 이전 활성 상태로 복구를 시도합니다. 각 플러그인의 정상적인 켜기·끄기 동작을 사용하므로 실행 중인 작업은 해당 플러그인의 종료 동작을 따릅니다.

기본 설정 목록 연결은 비공개 API·화면 구조를 이용하며 Obsidian 1.14.4에서 확인했습니다. 앱 버전이나 다른 플러그인이 같은 화면을 변경하면 추가 호환성 확인이 필요합니다. 그룹 화면을 사용하지 않을 때 반복 검사하는 타이머는 없습니다.

### 처리 시간 측정

1. 왼쪽 리본의 계기판 아이콘 또는 명령 팔레트의 **Performance Manager: 플러그인 처리 시간 보기**를 누릅니다.
2. **측정 시작**을 누르고 창을 닫은 뒤 평소처럼 글쓰기·탭 전환·Canvas 조작을 합니다.
3. 다시 결과 창을 열어 **측정 종료**를 누릅니다. 측정 중에도 약 10초마다 완료된 구간이 표시됩니다.
4. 플러그인 이름을 누르면 기록된 함수와 코드 행, 처리 시간 추정치를 볼 수 있습니다. **결과 복사**로 목록을 복사할 수 있습니다.

측정은 최대 10분 후 자동 종료되며, 마지막 결과만 이 플러그인의 `data.json`에 저장됩니다. 앱을 다시 켜도 마지막 결과를 볼 수 있지만 측정이 자동으로 시작되지는 않습니다. 다른 플러그인의 활성 상태·설정·노트를 변경하지 않습니다.

## 숫자의 의미와 한계

### Canvas 성능 오버레이 (0.1.1)

Canvas 우측 도움말 아래의 계기판 버튼으로 작은 오버레이를 열거나 숨깁니다. 배경·테두리·그림자는 완전히 투명합니다. 플러그인명·처리 시간·얇은 게이지를 표시합니다. 목록이 표시 높이를 넘을 때만 오른쪽에 얇은 반투명 스크롤바가 나타나며, 손잡이를 잡거나 휠로 목록을 이동할 수 있습니다.

- 위쪽 얇은 바를 드래그하면 이동합니다.
- 왼쪽 아래 작은 조절점을 드래그하면 가로·세로 크기를 바꿉니다. 오른쪽 위 모서리는 유지됩니다.
- 작은 측정 시작/종료 버튼으로 측정합니다. 오버레이에서 시작하면 큰 결과 창이 열리지 않습니다.
- 숨겨도 측정은 유지됩니다. 결과는 기존과 같이 약 10초마다 갱신되며 최대 10분 후 종료됩니다.
- 표시 여부·위치·크기를 저장합니다. 앱 재시작 후에도 적용되며, Canvas 영역을 벗어나면 안쪽으로 맞춥니다.
- 이동 바와 크기 조절점은 방향키로도 조절할 수 있습니다.

0.1.1은 격리 Sandbox에서 투명 배경·이동·크기 조절·조건부 스크롤·재시작 후 설정 유지를 확인했습니다.

- 약 2ms 간격의 V8 CPU 프로파일 표본으로 추정한 실행 시간입니다. CPU 사용률이나 현재 메모리 사용량, 플러그인 시작 시간이 아닙니다.
- 각 표본은 가장 가까운 플러그인 호출에 한 번만 배정합니다. 해당 플러그인이 호출한 앱 공통 함수의 처리도 포함될 수 있습니다. 상위 플러그인에 중복 합산하지 않습니다.
- 출처를 알 수 없는 처리는 별도로 표시합니다. 표본이 없는 플러그인을 0ms라고 단정하지 않습니다.
- 현재 Obsidian 주 창의 JavaScript 처리만 대상입니다. Worker·별도 창·GPU·전체 프로세스 사용량은 포함하지 않습니다.
- 처리 시간이 많다는 이유만으로 렉의 원인이라고 확정하지 않습니다. 함수명이 축약되어 있거나 이름 없는 함수일 수 있습니다.
- 측정 자체도 부하가 있습니다. 평상시에는 꺼두고 확인할 작업을 짧게 측정하세요. 약 10초마다 프로파일을 끝내고 다시 시작하므로 사이의 정리 시간은 기록 구간에 포함되지 않습니다. 화면에 경과 시간과 실제 기록 구간을 함께 표시합니다.
- 측정을 시작한 시점의 플러그인 목록을 기준으로 합니다. 측정 중 추가로 설치한 플러그인은 다음 측정에서 확인하세요.
- Electron의 내부 debugger 기능과 Obsidian 내부 플러그인 목록을 사용하므로 향후 앱 버전에서 호환성 확인이 필요합니다. 개발자 도구나 다른 프로파일러가 연결되어 있으면 측정을 시작하지 않습니다.

원시 프로파일·노트 내용은 저장하거나 외부로 전송하지 않습니다. 저장하는 것은 마지막 측정의 플러그인 이름·함수 이름·코드 위치·집계 시간입니다.

## 수동 설치

BRAT에서는 **Add beta plugin**에 `tlatndms2-droid/obsidian-performance-manager`를 입력해 설치할 수 있습니다.

릴리즈의 `manifest.json`, `main.js`, `styles.css`를 Vault의 `.obsidian/plugins/obsidian-performance-manager/`에 넣은 다음 커뮤니티 플러그인 설정에서 활성화합니다.

## 개발

Node.js만 필요하며 외부 빌드 의존성은 없습니다.

```sh
node scripts/build.cjs
node --test tests/*.test.cjs
```
